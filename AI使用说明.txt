AI 使用说明

这个项目是用 Claude Code（命令行 AI 助手）写的。下面如实说明用了哪些 AI 能力和工具、每样是怎么用的，以及 AI 生成的东西出过哪些问题、我是怎么检查和修正的。写这个文档，是为了让后面接手的人（或者我自己）知道代码是怎么来的，别把 AI 生成的东西当成本来就该这样。


一、用了什么

1. 模型
   项目全程在 Claude Code 里开发，当前驱动模型是 deepseek-v4-flash。说白了就是让 AI 按需求文档把整个项目从零写出来。

2. 实际用到的工具（都是 Claude Code 自带的）
   Bash 命令：查环境（node、npm、claude 版本）、装依赖、跑构建、跑真实的 claude 命令、git 提交推送、curl 验证。
   Read、Write、Edit：读需求文档、写代码、改配置。
   Glob、Grep：找文件、搜代码。
   TaskCreate、TaskUpdate：把大任务拆成清单，一步步跟踪进度。
   AskUserQuestion：在不确定时（比如推送用哪种认证）问用户。

3. 没用到的（也说一下，避免误会）
   没有拆子 Agent（整个开发就在主会话里连续做的）。
   没有用 slash Skill 来写功能代码。开发后期安装过第三方 skill 库
   mattpocock/skills（TypeScript 大神 Matt Pocock 开源的工程纪律 skill，
   15 个核心 skill 全局生效），但本项目没实际调用它们——项目是小体量
   GUI，用不上 tdd、code-review 这类重型工作流，装它们是给以后的项目用的。
   安装时用网页搜索确认过仓库信息。
   写功能代码时没有用网页搜索、网页抓取。

4. 一个不标准的隐藏工具：CDP（浏览器远程调试协议）
   AI 写的界面程序，光看代码没法知道它跑起来对不对。所以我额外写了几个临时脚本，用 CDP 连上真实跑起来的窗口，模拟用户点击、发消息的动作，再检查页面里有没有出现预期的内容。相当于给这个 GUI 程序做了自动化测试。


二、关键做法：先看真实输出，再写代码（不靠猜）

AI 最容易犯的错，就是照着文档猜。所以整个开发过程我坚持一件事：要写的功能必须先跑到真实输出，再动手写代码。

例子：
1. 要解析 claude 的流式输出，我先在命令行真实跑了一次 claude 命令，把输出的 JSON 一行行看明白：
   哪一行里有 session_id；
   文本增量到底在哪个字段（后来确认是 content_block_delta 里的 text_delta）；
   回复结束是哪个事件。
   确认了字段名，才写解析代码。写完之后，解析结果和真实输出完全对得上。

2. 要确认 Windows 上中文消息不乱码，我写了一个临时脚本，真实用 claude 发了一条带中文的测试消息，看到返回中文编码测试一切正常才放心。


三、AI 生成的东西，出过的问题和修正（按时间顺序）

1. 问题：依赖装不上。
   现象：npm install 卡在下载 Electron 二进制，报 ECONNRESET（网络被重置）。
   原因：这台机器直连 GitHub 不稳定。
   修正：改用国内镜像源 npmmirror 重装，一次成功。

2. 问题：claude 的流式输出格式不确定。
   现象：文档里只写了解析 stream-json，但没写具体字段。
   修正：不猜，先真实跑一次 claude 命令，照着真实输出写解析，最后用脚本验证文本增量、session_id、结束事件全部解析正确。

3. 问题：Windows 上调 claude 命令有编码隐患。
   现象：正常情况下要调的是 claude.cmd，但它要经过 cmd.exe 转发，中文参数可能乱码。
   修正：检查后发现 npm 全局安装的是原生 claude.exe，于是优先用 exe 的完整路径直接调，中文问题消除。

4. 问题：类型检查、构建不通过。
   现象：写完代码后，AI 自己跑 tsc 类型检查和 electron-vite 构建，报了一些类型错误和打包问题。
   修正：逐个改到类型检查和构建全部通过为止。

5. 问题：界面程序到底能不能跑，看不见。
   现象：这是桌面程序，光写代码不知道窗口里什么样。
   修正：用 CDP 脚本连上真实运行的窗口验证，结果证明：
   发第一条消息能拿到 session_id；
   第二条消息能接着上次的会话续聊（resume 生效）；
   流式文字在页面里真的在一点点变多（不是一次弹出来）；
   关掉再打开，历史聊天还在。
   第一次验证流式时用错了页面选择器，抓不到数据，改对选择器后就看到了文字实时增长。

6. 问题：代码推不上 GitHub。
   现象：git push 报 Connection was reset。
   原因：还是网络问题，GitHub 直连被重置。
   修正：检测到这台机器配置过代理 127.0.0.1:7897（说明装过代理软件），让用户把代理软件启动，再走代理推送，一次成功。

7. 问题：界面发消息后 claude 一直没回复（超时）。
   现象：CDP 验证时发现发出去的天气查询半天等不到回复，最后只落下一个空白的 AI 消息。
   原因：用和程序完全一样的命令去命令行里真实跑 claude，发现它一启动就报错退出：Input must be provided either through stdin or as a prompt argument。本机这个版本的 claude 在 -p 模式不再接受把消息当作命令行最后一个参数，必须从 stdin 喂入。
   修正：把传给 claude 的消息从命令行参数改成写进 stdin 管道（child.stdin.write 再 end），重跑验证，天气和搜索都正常返回了带来源的联网回复。

8. 问题：设置界面点保存后弹窗一直不关。
   现象：CDP 测试时，填完模型配置点保存，配置确实写进文件了，但弹窗还开着。
   原因：SettingsModal 组件保存成功后忘了调用 onClose()，只有点遮罩或取消才关。
   修正：在 onSave 成功返回后补上 onClose()。重跑验证，保存、关弹窗、下拉框更新、config.json 写入全部正确。


四、我的总结：AI 帮写代码的正确姿势

1. 让 AI 干活没问题，但每个关键环节都要用真实运行结果去验证它，而不是它说写好了就信。
2. 遇到不确定的东西（格式、版本、平台差异），先让 AI 去真实环境里跑一遍、看清楚，再写代码。
3. 项目跑通了之后，再花时间把临时验证脚本、调试代码清理干净，留下干净的项目结构。
4. 整个开发遵循能跑通、大于功能正确、大于界面好看、大于功能多的优先级，AI 被明确要求不许自作主张加无关功能。

一句话：AI 是写代码的主力，但检查和验证永远是用真命令来兜底的。
